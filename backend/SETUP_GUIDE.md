# Live Channel Setup (maintainer guide)

This folder provisions the portal's live data channel. **Nothing in the portal UI
references this folder** — it is for the platform maintainer only.

> **v6 note — no file edit needed anymore.** The channel endpoint and API keys
> are maintained from **Admin → Settings → Database & integrations** in the
> running portal: paste the endpoint URL, the Google Sheets API key and the
> Drive folder key, press *Save & apply now*, and the background data source
> used by every page switches immediately (it is stored in
> `DB.settings.integrations` and the independent `MDT_INTEGRATIONS` local key,
> so it survives demo-data resets). Editing `assets/js/channel.js` remains a
> fallback for pre-seeding the URL at deploy time.

## 1 · Create the data grid

1. Open [sheets.google.com](https://sheets.google.com) → new blank spreadsheet.
2. **File → Import → Upload** → select `database-seed/MDT_CampusOne_Seed.xlsx`
   → *Import location:* **Insert new spreadsheet** → Import.
   (Or upload the XLSX to Drive and open it with Google Sheets — File → Save as Google Sheets.)
3. Keep the sheet names exactly as imported — each sheet is one entity
   (`Students`, `Staff`, `Users`, `ODRequests`, `Timetable`, …). Row 1 headers are
   machine-readable; do not rename them.

## 2 · Deploy the channel

1. In that spreadsheet: **Extensions → Apps Script**.
2. Delete the default code, paste `Code.gs` from this folder, save.
3. (Optional) change the `TOKEN` value in `Code.gs` to your own shared secret.
4. Run the function `setup()` once from the editor and approve the permission prompts
   (it binds the spreadsheet and creates the Drive folder `CampusOne Portal Files`).
5. **Deploy → New deployment → Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
6. Copy the `/exec` URL.

## 3 · Wire the portal

**Preferred (v6):** sign in as the system administrator, open
**Settings → Database & integrations**, paste the `/exec` URL into the
*Google Sheets data channel* field (plus the API key and spreadsheet ID),
optionally fill the *Google Drive file database* key/folder, then press
**Save & apply now** — use **Test connection** to verify the channel answers.
Every page's background source reflects the new endpoint dynamically.

**Fallback (pre-seed at deploy time):** open `assets/js/channel.js` in the
portal and set:

```js
window.MDT_CONFIG = { API_URL: 'https://script.google.com/macros/s/…/exec' };
```

Remove the URL (or leave it empty) and the portal runs fully self-contained,
exactly as demoed.

## 4 · How data maps

| Portal entity | Sheet | Notes |
|---|---|---|
| Sign-in | `Users` | `role` decides which portal a user lands in |
| Students / staff | `Students`, `Staff` | `block` + `genderLock` drive warden scoping |
| Courses & loads | `Courses`, `CourseAllocations` | assigned-by = Academic Director |
| Timetable | `Timetable` | day 0–4 = Mon–Fri, period 1–8 (5 = lunch) |
| Approvals | `ODRequests`, `LeaveRequests`, `OutingRequests` | `timeline` stored as JSON text |
| Fees | `FeeHeads`, `FeeTransactions` | receipts generated by the office |
| Hostel | `HostelRooms` | `occupants` is a ` | `-separated list |
| Files / photos | Google Drive | `uploadFile` action, category folders |

## 5 · File storage

`uploadFile` writes into `CampusOne Portal Files/<Category>/` in your Drive and
returns a shareable link (viewer access). Use categories such as `Profile`,
`OD proof`, `Scholarships`, `Tickets`.

## 6 · Conventions

- All writes go through `add` / `update` / `remove` actions with the sheet name as `table`.
- Column A is always the record ID; the script auto-generates the next ID per sheet.
- Nested structures (approval timelines, ticket threads) are stored as JSON strings.
